# Use SpatialRuntime as a blocking external CI gate

## Why opt in?

A conformance decision has three states: **PASS**, **UNRESOLVED** and **FAIL**. An unresolved result is **not approval**. By default, the composite Action may exit successfully for UNRESOLVED so diagnostics can be retained without blocking research CI. If a project uses the result to gate a release, it must opt in to **PASS only**.

## Minimal blocking check

Paste this in your **own repository**, use the immutable merged commit of PR #91 (`d1951faad027fc55264759376980272788d4f874`) as shown below, and supply actual evidence under your ownership:

```yaml
name: Verify agent decision-to-execution binding
on: [pull_request]
permissions:
  contents: read
jobs:
  evidence-gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: Require grounded decision-to-execution proof
        id: verify
        uses: hippoley/SpatialRuntime/interop/conformance@d1951faad027fc55264759376980272788d4f874
        with:
          mode: decision-execution-binding
          file: evidence/decision-execution.json
          require_result: PASS
```

The evidence file must be generated by your own runtime. Do **not** copy SpatialRuntime's passing fixture to claim your runtime conforms.

| Verification output | Default Action exit | With `require_result: PASS` |
| --- | --- | --- |
| PASS | 0 | 0 |
| UNRESOLVED | 0 | nonzero |
| FAIL | nonzero | nonzero |
| Unsupported `require_result` | N/A | nonzero |

The real composite Action's three-way behavior and invalid configuration are exercised by [`conformance-consumer-gate.yml`](../../../.github/workflows/conformance-consumer-gate.yml).

## Assurance limits

- PASS is a consistency check **over the supplied evidence**, not independently observed real-world effects.
- A successful GitHub job in your repo does not by itself imply independent signoff of underlying runtime claims.
- Pin to an immutable SHA. The older `conformance-v0.1.0` tag does **not** include this added input.
- Using this in a third-party repository should be separately recorded as externally consumed **only after** independently inspecting its real run and production of evidence. An example in this repository, including this one, is never an adoption event.
